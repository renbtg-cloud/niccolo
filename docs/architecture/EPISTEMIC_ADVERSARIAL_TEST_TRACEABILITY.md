# Epistemic adversarial case traceability — AT-01–AT-26

This is an implementation audit against the owner-approved fictional cases in [the architecture review](EPISTEMIC_ARCHITECTURE_REVAMP_IN_PROGRESS.md#24-adversarial-conceptual-validation--first-round-25-cases) and its [AT-26 extension](EPISTEMIC_ARCHITECTURE_REVAMP_IN_PROGRESS.md#287-at-26--weaponized-formalism). It records executable witnesses, not a claim that the full fictional scenarios were reproduced or every possible failure excluded. The structured expert-authored MVP does not infer abstractions, truth, motives, or access rights from narrative text.

**Focused** means a listed integration test directly constructs the named failure mode and checks a corresponding invariant. **Constituent** means tests check relevant pieces, not the combined adversarial scenario. **Open** means the central distinction lacks a dedicated executable contract; listed tests are adjacent safeguards only. These are not percentages, maturity scores, or assertions of complete case coverage. Test references use `tests/<suite>.rs` and exact Rust test function names.

## Follow-through

Concentrate next on the explicit open AT-19 and AT-20 distinctions and the confidentiality boundaries in AT-06/AT-21. Prefer the existing contextual assessments, attributed actor state, identity, decision, and authorization machinery wherever it expresses the contract without false equivalence. Then add composed adversarial fixtures rather than treating the individual witnesses as proof of the whole. A test should demonstrate the precise failure it prevents and truth/authority boundaries it preserves.
